# ゲーム制作思想・共通制作原則（制作者の意図を次の作品にも引き継ぐための資料）

更新日: 2026-11-06
適用範囲: 『曼珠沙華』および今後のゲーム制作。作品固有の設定は各作品のCANONを優先。
位置づけ: 会話から整理した制作方針。本人が未承認の細部は確定設定として扱わない。

## 1. 目指す作品
- 遊びとしての面白さだけでなく、**美しさ・手触り・情緒・記憶に残る体験**を大切にする。
- レトロゲームへの愛着を基礎に、現在の技術で色彩、演出、操作性、遊びの幅を発展させる。
- 作品世界、キャラクター、機体、武器、音楽、ステージ、物語が互いに意味を持つ設計にする。
- 試遊できるものを早く作り、見て触って判断し、変更を素早く反映する。Steamで販売できる完成度を目指す。

## 2. 制作で特に重視すること
1. **決めた設定・デザインを守る。** 承認済みの顔、髪型、色味、衣装、名前、性別などを無断で変えない。
2. **見栄えだけでなく実際に使える素材を作る。** 一覧絵やコンセプト画と、実装用素材は別物。
3. **素材は独立して再利用できる形にする。** 人物は一人ずつ、背景透過PNG。機体は縦用上面・横用側面、アニメーションはフレーム別、音は独立ファイル。
4. **設定と素材が生まれたら速やかに共有する。** GitHubを共通の正本にし、Codexや他の開発担当が参照できるようにする。ただしチャットからの自動同期を前提にしない。
5. **実施状況を正確に報告する。** 「案」「制作中」「GitHub保存済み」「ゲーム組込済み」「動作検証済み」を混同しない。保存先、コミット、PR、検証内容を示す。
6. **完成を急ぎつつ勝手に決めない。** 細部の案は積極的に提示するが、重要な設定や承認済みアートの変更は本人の承認が必要。
7. **繰り返し指示させない。** 決定事項、差し戻し理由、未完成の課題を継続的に記録する。

## 3. 『曼珠沙華』で表れている好み（作品固有の例）
- 『沙羅曼蛇』『R-TYPE』『グラディウス』『ロックマン』『ツインビー』『エリア88』などの魅力を参考にしつつ、独自の世界観を作る。
- 横・縦スクロールの変化、複数周回で世界線・敵・ボス・音楽・色・進行が変化する設計。
- 1～3人協力、キャラクターごとに異なる攻撃成長、3人の連携技。
- 弾幕は派手で美しく、ただし視認性を犠牲にしない。爆発や撃破の爽快感を重視。
- 音楽は8ビット調、哀愁、雅楽的な響き、少し不気味な気配、躍動感。場面と周回に合わせて変化。
- 花言葉、再会、悲しい記憶、世界線の変化を物語と演出に結びつける。
- 既存の承認済み主人公（コルミィ、ジヨーザ、マフィオ）の外見は固定。ムゥ等も承認済み原画を優先。
- ゲーム本編に加え、設定資料、アートブック、小説、漫画など世界を深める表現も重視。

## 4. 別作品にも通じる考え方
- 『SNOW CRYSTAL LAB』では科学的な仕組みを遊びに変えながら、結晶成長の透明感や幻想的な美しさを重視。
- ジャンルが違っても「見ていて美しい」「触るほど発見がある」「世界のルールに一貫性がある」ことを目指す。

## 5. AI・Codex・制作担当への具体的な作業規約
- 着手前に本書、作品CANON、承認済み画像、最新の指示・素材台帳を読む。
- 画像を新規生成する際は承認済み原画を参照し、勝手な顔・衣装の再解釈を避ける。参照できない場合は同一と主張しない。
- UI込みの一枚絵を雑に矩形切り出しして「透過済み完成素材」と呼ばない。
- PNGのアルファ、輪郭、欠損、画像サイズ、フレーム整合性、Godotでの読み込みを検証する。
- 素材名、用途、縦横、アニメーション情報、出典、承認状況をmanifestに記載。
- 新しい設定や素材は作業ブランチにコミットしPRで提示。既存の承認済み素材は無断上書きしない。
- 未承認案を正式設定へ昇格させない。未確認のメール送信・GitHub反映・ゲーム実装を完了と報告しない。

## 6. 判断に迷ったら
「見た目は華やかだがゲームに入らない」より「実装できて原画に忠実」を優先。
「新しい案で顔を変える」より「承認済みの顔を守る」を優先。
「大量に作ったと言う」より「使える品質を検証して正確に報告」を優先。
「AIの都合で作業を分断する」より「制作者が一度決めたことが次の工程に伝わる」を優先。

## 7. 更新方法
制作者が制作思想を追加・訂正したら、この文書に日付付きで追記し、作品固有の設定変更は作品CANONへ別途反映する。AIが推測した好みは『提案・未確認』として扱う。
