# 全ブランチ確認・指示書更新ルール（2026-11-20 ユーザー指示）

**対象は特定のブランチではなく、リポジトリ内の全リモートブランチと全未統合PR。** 毎回のCodex/Antigravity作業開始時、git fetch --all --prune の前に git status で作業中変更を保護し、fetch後に git branch -r、GitHubのPR一覧（draft含む）を取得する。mainだけ見て着手しない。

1. 全ブランチを列挙し、最終コミット、mainとの差分、対応PR、作業内容、競合・重複・依存関係、テスト状態、マージ可否を一覧にする。削除済み・アクセス不能なブランチはその旨を記録し、確認済みと偽らない。大量の場合は一覧を機械的に取得し、未統合・最近更新・関連するものを優先して中身を精査する。全件のコード全文を毎回読むことまでは要求しない。
2. 新規作成したブランチ・指示書・素材は必ず一覧に登録し、次回セッションでも発見・参照できるようにする。特に design/enemy-visual-catalog-20261120 の docs/design/ENEMY_VISUAL_CATALOG_20261120.md を敵・背景制作の開始前に確認。
3. 新たな指示書を作る・更新する際は、必ずこの全ブランチ確認ルールをその指示書に明記するか、本書への参照を追加。AGENTS.mdを最上位の入口とする。文書だけで実行や自動起動は保証されない。
4. 重複PRは差分を照合して一本化を検討。安全性・Godot4.6実行・テスト・競合解消が確認されたものからmainへ統合。未検証のものを勝手にマージしない。承認済み素材・設定・セーブを保護。
5. 作業終了時に、確認した全ブランチ数・一覧取得日時・未確認の理由・今回実際に精査したブランチ・新規ブランチ・統合済みPR・残課題を HANDOFF.md と NEXT_ACTION.md に残す。古いブランチは勝手に消さない。

最優先の製品目標はPR #325などの第1面→ムゥとの会話→第2面をGodotで通し検証し、本編へ統合すること。資料追加だけで開発完了としない。
