# ストーリー拡張・差し替え設計ルール

## 目的
物語の追加・改稿・周回分岐を、既存ゲーム進行・素材・セーブとの矛盾や破壊を最小限にして実施する。

## 変更に強い構造
- 会話本文、話者、表情、イベント条件、世界線・周回条件をデータとして分離し、戦闘ロジックに直接埋め込まない。
- 各イベントには永続的なIDを付与し、表示順と識別子を分離する。削除より非推奨化・置換先ID指定を優先する。
- 章・ステージ間に追加イベント用フックを用意し、条件不一致・未定義イベントは安全にスキップする。
- キャラ名・人物関係・機体設計・時系列・世界線ルールを設定台帳に集約し、イベントから参照する。
- 決定済み・提案・保留・廃案を分離。未承認案は正式シナリオに自動反映しない。
- 各世界線の真実と登場人物が知っている情報を区別し、会話のネタバレや時系列矛盾を防ぐ。
- 選択肢とフラグはバージョン管理し、旧セーブからの移行・欠損時の既定値を定義する。
- 原画・顔・機体・BGMは論理アセットID経由で参照し、差し替え時も参照元を変えずに済むようにする。

## 変更時の確認
1. 変更箇所の依存イベント・登場条件・既存台詞を洗い出す。
2. 1〜4周目、8ステージ、ムゥ／クゥ／エリィ／マリィ／主人公3人の関係と矛盾しないか確認する。
3. 既存の正式素材を上書きしない。新規画像は別ファイルとして追加し承認後に参照を切り替える。
4. イベントの存在・順序・スキップ・旧セーブ読込・未定義IDを自動テストする。
5. Godotで実際の画面遷移と会話を確認して初めて「実装完了」とする。
