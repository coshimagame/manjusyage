# 曼珠沙華 HUD・弾幕・アイテムの視認性と美術強化

作成：2026-10-31
区分：ユーザー要望の方向性と、Codex向け実装検討仕様（未実装）。以下の具体的な寸法・色・記号の提案は未承認のデザイン案。正式な完成品と混同しないこと。

## ユーザーの直接要望
- 「弾幕の演出が地味すぎるから派手に」「美しく散る感じ」：花弁／火の粉／光片が広がって儚く消える上質なエフェクトへ。
- 「視認性は大事」：画面を美しくしても自機・敵弾・アイテム・当たり判定を見失わないこと。
- 「アイテムもグラフィックしょぼかった」：小さい四角と文字の仮表示を脱し、意味と価値が伝わるピクセルアートと取得時の手応えを作ること。
- 「ステータス部分も工夫必要、UIデザイン」：ゲーム中HUDを作品固有の美しいSF計器として刷新し、3人プレイ時も瞬時に判別できるものにすること。

## 実装監査（コード確認のみ・実機/スクリーンショット未検証）
- Godot 4.6のゲーム本体 `game.gd`、論理解像度640×360。
- `draw_hud()` は上33px（P1〜P3、4マスHP、弾色、3px高のチャージ）＋下23px（面名、音声、進捗）。名前・能力の日本語はy=43にあり、プレイ領域にかかる。上部右端はスコア／残機／コンボ。
- `_draw()` の敵弾はピンクの矩形＋白い芯、アイテムは12×12pxの線枠＋「+」「E」文字。現行実装のアイテムは**HP回復(kind 0)**と**エネルギー回復(kind 1)**の2種だけ。パワーアップ・ボム等を実装済みのように記述しない。
- `players` はHP 4、チャージ0〜100、`down`（救助待ち）、`rescue`、`inv`、キャラ固有状態。シールド・継承武器等の将来UIは提案段階。
- 混合スクロールの縦区間も `draw_hud()` を使うため、横・縦両方を検証すること。

## HUDのレイアウト案（未採用、推奨実装基準）
- 640×360の**既存プレイ可能領域を減らさない**。上端約33〜40px、下端既存23px程度を目安とし、プレイヤー移動領域との干渉を先に検証する。
- 画面上端：左からP1・P2・P3の個人パネルを最大3枚、右にチームのSCORE・RESERVE・COMBO。各個人パネルにP番号＋正式キャラ名、耐久4区画（視認可能な大きさ）、必殺／エネルギーゲージ、使用可能時READY印。人数1/2/3で不自然な大きな空白を作らない。
- キャラ名の白文字は常時可読、枠や小さなアクセントに個別色を使う。個人の固定識別色と可変武器色を混同しない。「色だけ」では識別しない。
- 最重要情報（残りHP、ゲージ満タン、救助待ち）は常時見え、被弾／満タン／救助は**短い変化**で目立たせる。常時の明滅・大量の装飾・小さすぎる文字は禁止。
- 細い金属調フレーム、暗い半透明パネル、控えめな紅／金の装飾。曼珠沙華の花弁／共鳴線はフレームの隅と満タン時だけ。UIをアートブックから独立した「汎用SFテンプレート」にしない。
- 下部は必要な面情報と進捗を簡潔に。入力ヘルプや音声切替説明は常時表示せず、一時ヘルプやポーズ内へ移す提案。ボスHPは上部と重ならず、HPの桁・弱点表示を潰さない位置にする。
- 背景とUIで明暗差を確保し、整数拡大時のドット輪郭を維持。日本語のSystemFont利用が環境依存なら実機で代替表示も確認。

## 弾幕とパーティクル
- 花がほどけるように美しく散る：まず中心の明光→少量の花弁・火の粉・光片の速度差→短い余韻。激しい連射時は過剰な残像を削減し、敵弾の軌道を最優先。
- 当たり判定の芯と危険性はエフェクト無しでも判別可能にする。敵弾と味方弾の外形を分け、攻撃、無害な散り粒、収集可能アイテムをシルエット・明度・動きで区別。
- ボス攻撃の花状円環・扇状配置は**ゲームプレイ上の調整が必要なデザイン案**であり、弾数・弾速・ヒット判定を独断で変更しない。
- パーティクル数の上限、短い寿命、低負荷設定（演出量の設定値）を持たせ、最大3人プレイ時の60fps目標を計測する。画面全体Bloomは避ける。

## アイテム（既存2種から改善）
- **HP回復（kind 0）**：ハート／装甲紋章などの独特の輪郭、4方向から見ても回復と分かる記号、強めの外周と安定した明度。
- **エネルギー回復（kind 1）**：稲妻／輝晶／充電セルを思わせる別の輪郭とリズム。HPと**形状でも**区別。
- 12×12px枠＋1文字から、少なくとも2〜3段階で陰影を持つ自作ピクセルアイコンへ。派手な光輪は拾うまでの常時表示よりも**取得瞬間の0.15〜0.3秒**に集中。演出位置で当たり判定を誤認させない。
- 将来の特殊武器、スコア片、シールド等の種類は追加提案。アイテムを勝手に増やし既存の取得効果・セーブ仕様を変えない。
- アイテムのモーションは緩い上下動＋狭い光彩、取得時は小さな開花／光が自機へ吸い込まれる印象。視認性を損ねる回転や不規則な色変化はしない。

## Codexへの作業順序・受け入れ基準
1. 実ゲームでタイトル／1人道中／3人道中／ボス／縦スクロール区間を撮影し、HUDとアイテムの見にくさを具体的にメモ。
2. まずHUDの重なり・文字の小ささ・体力とゲージの判別性を直し、**HP4・チャージ0/50/100・1/2/3人・ダウン救助**を実数値で表示検証する。
3. 既存2アイテムを描き直す。アイテムが敵弾と重なった場合も識別でき、取得判定・回復効果が変わらないことを確認。
4. 「美しく散る」弾幕ヒット／消滅エフェクトを実装して視認性・負荷を再テスト。
5. 640×360の実ゲーム前後画像とGodot起動・既存1〜3人自動攻略/保存/音声などのテストを記録。自動攻略は実機手操作の検収とは別。
6. `HANDOFF.md`, `docs/CHANGELOG.md`, `ART_ASSETS.md` に実変更・未解決・画像の出所と位置を記録。未実装を実装済みと報告しない。

最優先は**読みやすいゲームプレイ**。美しさはその前提を壊さない方法で達成する。
