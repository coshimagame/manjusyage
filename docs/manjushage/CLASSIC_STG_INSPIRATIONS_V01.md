- 研究対象の**固有名詞・キャラ・敵・機体・ロゴ・画面構図・スプライト・弾の具体配置・シナリオ・音楽旋律・SE・ゲーム内文章・UIアイコン**をそのまま複製しない。スクリーンショットを描き起こして製品に使わない。
- 参考作品名を残すのは**内部研究資料**だけ。「公式コラボ」「移植」「許諾済み」のように見える商用表記はしない。
- 一般的な設計アイデアの研究、ジャンル上の操作感、リスク報酬の発想を取り入れ、**タイトル・SF世界観・3人の個性・花色・世界線変化**によって独創的にする。

## 試作A — 記憶花晶（仮）／アイテムに意志を持たせる
既存Godotに実装済みの HP回復(kind 0)／エネルギー回復(kind 1) を保持。新ギミックは**追加提案**であり、現在のアイテム実装と混同しない。
- 小さな「光の種」を拾うと即時に通常資源（緩やかなチャージ）になる。
- 画面に一定時間留めると**小さく開花**して別の資源効果へ変わる。ただし敵弾・背景に混ざらない形状、残り時間の明瞭なインジケーターが必要。
- 種の内部芯は同じ形だが**状態アイコンと花の開閉形状**を差別化。世界線により花弁の装飾色は変わっても効果識別は固定。
- P1/P2/P3の奪い合いを避け、チーム共通資源か個人用かを後から選べるプロトタイプに。プレイ不能な状況で人質的なアイテム放置を強制しない。
- まず**ダミーとして1種類**のみで試し、必要・面白い・見えるが確認できてから実ゲームのドロップテーブルへ導入する。

## 試作B — 護り花弁（仮）／「装備を配置する」戦術
- 自機に追従する花弁の光の小盾。前／後／収束を切り替える場合、**当たり判定をユーザーへ明示**。現状のシールド／被弾後無敵／周回弱体化の設定を上書きしない。
- 敵弾の一部を防ぐ（全部は防がない）、持続時間・再使用・チャージを持つ。巨大な無敵防御体や原作機体と同じ輪郭・挙動は採用しない。
- ソロ・協力の格差を生まない。2〜3人時は連携配置で**わずかな相乗効果**を仮実装するが、効果半径を大きくして画面の弾幕を覆わない。
- キャラ固有性能案：コルミィは短い高出力連動、ジヨーザは弱点解析で効率向上、マフィオは吸収した敵弾の攻撃方式を変換。いずれも**具体数値未確定**。

## 試作C — ムゥの開発選択／戦闘以外の面白さ
- ステージ間の整備室（仮）で**二択の武器開発**。ユーザー既存設定：短期で完成する案vs長期・高性能案、クリア数で完成する。店で武器を買う構造をそのまま持ってこない。
- 試作画面は**二つの兵装のシルエット・使用時エフェクト・完成までの面数・仮の性能差**が即座にわかる。コルミィ、ジヨーザ、マフィオで体験が異なるが、どれを選んでも詰まない。
- マフィオ捕食技・ボス継承武器・既存セーブへの作用は未決のため、最初は**装備選択の仮UI＋進行状況データモデル**。実ゲームセーブとの統合は保存互換テスト後。

## 試作D — 各世界線に「違うステージを遊んだ」感覚
- 4周の花色案は**緋紅・白銀・青紫・黄金**（AI仮パレットで、ユーザーが承認した具体色ではない）。
- 1周：学習可能なシンプルな弾の予告、地形の脈動／ムゥが亡くなる運命。
- 2周：同じ場所に過去の痕跡と救出につながる防御・位置取り課題／ムゥ生還。
- 3周：2系統の空間法則が重なり、敵の連携と花の二重開花。見た目だけでなく**地形の挙動**が変わる。
- 4周：敵がプレイヤーの従来行動に対策。ボスの段階攻撃、散りゆく黄金の花。コルミィ・ジヨーザ・マフィオの個性がそれぞれ攻略で活きる。
- 敵弾の重要色（危険/通常）、味方・アイテム・無害な花弁の**識別**は周回で変えない。ボスの攻撃中に視界を埋める「綺麗さ」は不採用。
- 横スクロール・縦スクロールの構成は一つの周回を固定で交互に模倣するのではなく、世界線で自然に変わる地形・演出に同期。

## 最初に動作させる順（Godot 4.6 / 640×360）
**第一パッケージ**：
1. 既存横→縦→横の混在スクロールがどこで始まるかを現行コードで調べ、実ゲーム画面の比較を取得。
2. ステージ1の**世界線花色4種プレビュー**を実装。実ストーリー周回未実装ならデバッグ用プレビューに限定。ゲームの選択難易度5段階とは別変数。
3. HP/チャージアイテム2種を**既存の描画を改善**。武器アイテムの追加はまだしない。通常弾の発射・花が散るヒットエフェクトを、視認性とコントラストで比較。
4. 3人で遊べる**簡単な共鳴花陣演出＋ソロ代替**をスコープ小さめの体験版に。画面を隠さない。
5. 画面をキャプチャし、Godotの起動・1/2/3人、保存、実機コントローラー、音楽、縦区間、ボス、60fps目標（計測値）を確認。実機未検証は未検証と明記。
6. 機能が成立したら記憶花晶（仮）、護り花弁（仮）、ムゥ開発画面へ順に進む。舞台や世界線との整合性が崩れた時点で見直す。

## 採用判断のための評価軸
1. 遊んでいて**良い意味で悩む選択**があるか（敵を撃つ以外の判断）。
2. 最初の30秒で操作・アイテム・危険弾の意味が読めるか。
3. 3人協力が楽しい一方、**ソロでもストレスなく完走できる**か。
4. 世界線を回すと、色以外にも**道・敵の動き・音・武器の使い方**が変わるか。
5. 元の4作品に詳しい人にも、**曼珠沙華固有の世界観と体験**として認識されるか。
