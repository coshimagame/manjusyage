## 優先順位
1. **ユーザーの明示的な最新決定**（例：「ジヨーザ」への改名）
2. 公式設定台帳にある「決定」
3. 企画採用（ユーザーに相談した案を含むが、未確定要素を含む）
4. 提案（ユーザー未承認）
5. 旧案・初期試作（実装物も物語の正史とは限らない）

実装状況は必ず実コードと [../../HANDOFF.md](../../HANDOFF.md) と [../CHANGELOG.md](../CHANGELOG.md) を確認する。旧称のGitHubリポジトリ `coshimagame/starlink-squad` は既存のGodot 4.6試作。**リポジトリ名を作品タイトルに合わせて無断変更しない。**

## Codexの約束
- 資料にない属性（年齢、性別、家族関係、外見、ヒカリとの関係）は勝手に正史化しない。
- 追加した設定は先に台帳に記録し、他の資料と突き合わせる。
- 変更前の文章・絵を消さず、旧版として保存する。
- 「決定／提案」と「実装済み／未実装」を別の軸で記録する。
- 企画資料集はネタバレに応じて公開版・開発者版に分けられる構造で作る。
