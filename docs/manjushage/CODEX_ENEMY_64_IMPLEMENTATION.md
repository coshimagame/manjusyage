# 64体の敵PNGをゲーム本編へ組み込む実装指示
2026-11-06 / Mw-fActory

## 目的と現在地
assets/enemies/manjushage_64_v1/ の64体（各ステージ8体）をゲームの敵描画に使用する。
このPRは素材と指示書の取り込み。敵の出現・描画処理は未変更で、Godot実行検証も未実施。
ギャラリー表示だけで実装完了にせず、実際の戦闘中に対応するPNGが描画されることを確認する。

## 最初に読むもの
AGENTS.md、HANDOFF.md、docs/DEVELOPMENT.md、docs/manjushage/CANON.md、STAGES.md、ENEMIES.md、CODEX_VISUAL_ALIGNMENT_PROMPT.mdを読む。
最新mainと作業ブランチの差分、未コミット編集を確認。mainへ直接書き込まず、新規ブランチとPRで作業し、マージしない。

## 素材と識別子
- 原本: assets/enemies/manjushage_64_v1/manifest.json、README_FOR_CODEX.md、original_concept_sheet.png、source_crops/、sprites/。全131ファイルをZIPと同じバイト列で保存。
- 実装には同フォルダーのmanifest.runtime.jsonを使う。原manifestのsource_imageはZIP内に存在しない旧ファイル名のため、この派生版でoriginal_concept_sheet.pngへ補正。
- manifestのパスは素材フォルダー相対。Godotではres://assets/enemies/manjushage_64_v1/を接頭辞にする。
- 安定ID S01E01〜S08E08とstage/slotを使う。仮の敵名・画像中の文字を正式名称として採用しない。
- 画像の4〜8面の名称は現行STAGES.mdと異なる。数字のstageを対応キーにし、ゲーム側の名称・物語を改名しない。
- 元画像は一覧画からの自動切り出し。透過は仮処理。方向別の側面図・上面図、攻撃・撃破アニメーションはない。

## 実装手順
1. 64件を一度読み込む敵素材カタログを用意する。IDの一意性、stage/slot、全パスを検証し、Texture2Dをキャッシュ。毎フレームのファイル読み込みは禁止。
2. game.gd、art_catalog.gd、vertical_passage.gd、既存敵の生成・描画を確認。敵インスタンスのasset_idを移動・攻撃パターンIDと別に保持する。同じ行動でも別画像を選択できる構造にする。
3. まず1面の8体を実戦の出現テーブルに割り当て、既存の敵描画に対応画像を接続する。全64件のステージ別登録と横・縦両方の検証シーンを用意する。
4. 2〜8面の戦闘が未実装なら、未実装のまま明記してステージ別の試験出現経路を作る。未完成のステージを完成扱いせず、将来本編の出現テーブルから同じIDを使えるようにする。
5. nearestフィルター、縦横比維持、中心基準の描画を使う。画像寸法136/137×76を当たり判定サイズとして流用しない。既存の判定・HP・速度・弾幕・セーブ互換を守る。
6. 横スクロールと縦スクロールで同じ静止画を暫定使用可能。単純な90度回転で別視点の完成素材にしたと報告しない。反転・回転は個体の見た目を確認して設定する。
7. 黒・白・実際の背景で全64体の輪郭、黒抜け、文字混入、隣の敵の混入、切れを確認。不具合はIDで記録し、修正画像は別の派生フォルダーに保存する。承認済みart/activeや原本を上書きしない。
8. PNGが欠けた場合はIDとパスを明示し、既存描画へ安全にフォールバックする。正常時にフォールバックだけを表示して合格としない。

## 検収条件
- 64個のID、1〜8面×8スロット、全Texture2Dロード成功。
- 全64体を横・縦の試験出現で表示し、IDつき実ゲーム画像を保存する。
- 1面の実戦で8体の割当と描画を確認。2〜8面の本編と試験シーンを区別して報告する。
- Godot 4.6 Standardでインポート・パース検査。docs/DEVELOPMENT.mdに従い、隔離したuser://で1〜3P、縦区間、ボス、保存、入力・音楽の回帰を実施する。
- 実画面で敵弾・自機との識別、縮尺、透過、画面端、3P時の視認性を確認する。
- Windows書き出しでPNGとJSONが収録されることを確認。必要ならexport_presets.cfgのJSON収録設定を調整する。
- HANDOFF.md、docs/CHANGELOG.md、NEXT_ACTION.mdへ変更、実施した検証、未検証事項を記録。PRでレビュー可能にする。
- 自動テストは物理パッド・手動プレイの検収と区別する。素材登録と全8面の完成を混同しない。
