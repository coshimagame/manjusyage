# Windows試遊版：ステータス・ステージ間ストーリー・アイテム実装タスク
更新：2026-11-06
状態：実装指示（**コード実装・ビルド・動作検証は未完了**）

## 重要な前提
- 対象は**Windows試遊版**。Godot 4.6。Web版は後続の互換性検証。
- 以前ユーザーが承認した**正式なキャラ画像・アイテム画像をそのまま採用**。最近生成した別の参考画像で置き換えない。
- 元画像が見つからなければ探索したパスを報告し、画像未発見として保留。別画像を「正式素材」と偽装しない。
- 既存の1～3人ローカル協力、コントローラー、プレイ進行を壊さない。既存の正史Markdownを優先。

## 1. 詳細ステータス画面
- 通常HUDはプレイに必要な最小限（各プレイヤーの識別、耐久/シールド、現在武器、ボム、取得効果）に限定。
- ポーズ/スタートメニューから**詳細ステータス**を開ける。3人協力時は全員を切替表示できる。入力競合・ポーズ解除の誤操作を防ぐ。
- 3人：コルミィ、ジヨーザ、マフィオ。正式キャラ肖像と表情差分を使用。表示項目は**運気、解析、攻撃、防御、武器、特殊能力、成長、取得効果**。数値や能力効果が未確定の場合は仮定を仕様書に明記し、ゲームロジックと矛盾させない。
- 16bit/SFC風の豪華なパネル、明瞭な文字、3人分の配色、ゲームパッドで操作可能。
- 完了条件：Windows版でメニューを開く→キャラを切り替える→各能力と実際の効果が整合→ゲームに戻れる。

## 2. 各ステージ間ストーリー
- 全8ステージ間に会話イベントを差し込める**データ駆動のシーンランナー**を実装。立ち絵、話者名、台詞、表情、背景、効果音、ページ送り、スキップ、既読を持つ。
- 各世界線/周回、難易度に応じてイベント分岐可能な構造。セーブ/再開と整合。
- **承認済み正史**のみ確定台詞として採用。未決のクゥ・ムゥのやり取り、エリィ・マリィ、7面と8面の展開は未承認の台詞を勝手に正史化しない。
- プロローグ冒頭にはクゥがムゥに人外のモノたちの説得を打ち明ける会話を置く方向。ただし演出台詞は仮稿扱い。
- 各ステージの詳細な台詞が未完成でも、ステージ間イベントの起動/終了/スキップとデータ差し替えを先に動作させる。
- 完了条件：1面クリア→ストーリー表示→2面へ移行、以降の面にも接続口があり、分岐・スキップ・復帰が動く。

## 3. 既存アイテム画像の反映
- リポジトリと既存資料、素材保存先を調査し、正式画像の対応表（アイテムID→画像パス→HUD画像パス）を作る。
- フィールド上の取得物、HUD、取得通知に同じ正式素材を使用。欠損アセットは明示的に記録。
- 画像差し替えがコード修正なしでできるようにResource/データ定義で管理。
- 完了条件：取得前後に画像が表示され、ゲーム再起動後も参照が切れない。

## 4. アイテムの効果
- アイテムごとに**効果ID、対象、持続、重複/上限、取得条件、UI表示、効果音**を定義。
- 武器強化は実弾の威力/射程/連射/形状など実際の攻撃ロジックに反映。シールドは実ダメージ処理に反映。ボムは使用と残数表示に反映。運気・解析など能力との関係は既存正史を確認し未決なら提案に留める。
- コルミィの出力の揺らぎ、ジヨーザの着実な強化、マフィオの捕食→能力転用という固有性を既存仕様と矛盾なく統合。
- 3人協力時の所有者、同時取得、死亡時の扱いをテストする。
- 完了条件：各アイテムを取得→目視/ログ/数値で効果を確認→HUDが更新→セーブ/ロードでも破綻しない。
