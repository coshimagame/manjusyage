# 『曼珠沙華 / MANJUSHAGE』アートブック再編集・総監督指示
企画改訂日: 2026-10-30
ステータス: ユーザーからの再編集依頼／現行版 v0.1 の改善指針
既存原稿: `books/perfect-guide/v0.1/`（**上書き禁止**）

## 0. ユーザーが求める作品
「Codexの設定資料集が色気なく、説明文ばかり。グラフィックデザイナー、ブックデザイナー、小説家、編集者、科学考証者を制作チームに加え、**想像の挿絵もゲーム画面も大量に載せた、眺めるだけでも心を奪うアート本**として作り直す」。
PDFを枚数だけ増やしてはならない。1ページごとの絵の強さ、物語の余韻、レイアウトのリズムを設計すること。

## 1. 制作チームをロールとして分業する（単なる肩書きではなく、各レビューの提出物を作る）
1. **アートディレクター**：芸術面の統一、カバー、象徴（花・宇宙・機体）、造形の一貫性。アートバイブル、キービジュアル選定と不採用理由。
2. **グラフィックデザイナー**：色彩・文字の階層・図形言語・全図版の配置。ページ共通グリッドと各章の変奏。
3. **ブックデザイナー／エディトリアルデザイナー**：見開きの起承転結、余白、視線誘導、紙面の強弱、製本余白、印刷／電子両対応、版面の原本。
4. **小説家／シナリオライター**：長い説明を短い印象的な文学的シーンへ変換。痛みと希望、喪失と再会。設定を勝手に確定せず「物語断章」と「正史」を区別。
5. **編集者／校閲者**：事実・設定矛盾・物語の伏線・章の密度・名前の統一・タイポグラフィ・読者目線の欠落を検査。
6. **科学考証者（ハードSF監修）**：「虚構の内部論理」を強化。記憶情報、世界線、エネルギー保存、時間と因果、生体機械に明確なコスト・制約・反証可能性を設ける。現実の科学事実と創作理論を厳格に分離。
7. **ゲーム撮影監督**：本物のGodotビルドの画面をシーン別・プレイヤー数別に撮影し、ビルド番号・撮影条件を登録。
8. **設定考証／アセットアーキビスト**： `docs/manjushage/CANON.md`, `CONTINUITY.md`, `ART_ASSETS.md` と全画面・全イラストをIDで結ぶ。
9. **印刷品質管理**：フォント埋め込み、画像解像度、クリッピング、ページ数、塗り足し、版権・出所、PDFをレンダリングし全ページを目視検収。

## 2. 方向性／美意識
- キーワード：**残酷なほど美しい宇宙、記憶の花弁、触れられない再会、機械と生物の境界、生命の赤、孤独な青、希望の金。**
- 感情曲線：圧倒的な美しさ → 不穏 → キャラクターの親密さ → 戦闘の熱狂 → 喪失 → 真相 → 希望。
- ビジュアル：繊細な和の曼珠沙華の形、レトロアーケードSF、16-bitの精緻なピクセルアート、重厚な現代SF設定画。**かわいらしさも荘厳さも**共存させる。
- カラーパレット案：深宇宙 #090C1F、記憶の紅 #C32249、淡金 #D5B26A、群青 #446CA3、静かな白 #F0EBE2。企画提案であり決定事項ではない。
- 文章は表組み・注意書きでページを埋めない。物語の余韻をつくる一行のコピー、短い詩、画面に寄り添う200～500字の物語断章を多用。
- 大見出し・和文・欧文の対比、文字のサイズ差、見開きの大胆な構図、静かな白ページを活かす。**装飾過多・同じフォーマットの繰り返しは禁止**。
- 固有名詞の誤表記禁止：**コルミィ、ジヨーザ（ヨは大きい）、マフィオ**。
- **ジヨーザは男の子（ユーザー決定）**。コルミィとマフィオの性別、3人の具体的な外見、年齢、衣装は未決。描いた案は必ず「デザイン案01・未採用」と記す。既存の公式設定にない情報を勝手に正史にしない。
- **既存の参考コラージュにある青髪の女の子姿はジヨーザの正式デザインとして使用禁止**。今後のジヨーザのキャラクター画は、知的で計画的な**少年**として表現する。容姿・髪型・服装等は未採用候補として複数案を作る。

## 3. 本の目標
- **まず24～32ページの高密度な試作**（表紙／扉／世界観／3人／機体／協力技／生体ステージ／巨大ボス／ゲーム実画面／短編／編集後記）。
- ユーザーのデザイン承認後、**96～128ページの本編アートブック**へ展開。初回から読者が最後まで楽しめる見本を作る。
- B5縦判を初期提案。A4・正方形なども比較できるが、未確認のまま仕様を「ユーザー決定」と書かない。
- 完成版は**原則として見開きごとに主役となる実ビジュアルを1点以上**、全編で多数（目標60～100点の図版／実画面／デザイン研究。実際の制作状況に応じて調整）を用意し、ギャラリーとしても成立させる。
- 完成時の文章比率は視覚中心に。大半を同じサイズの本文段落で埋める現行レイアウトをやめる。
- ページ順、アート、文字、キャプションを**編集可能な原本**として保存し、印刷PDFは生成物として出す。

## 4. 図版の3種を厳密に区別する
### A：実ゲーム画面「IN-GAME CAPTURE」
本物のGodotゲームを起動して撮影したPNG。タイトル、プロローグ、道中、3色リレー、仲間救出、バースト、ボス、ゲームクリアなど。
- 各画像に **ゲーム版 / 撮影日時 / 撮影環境 / 解像度 / 対象シーン** を記録。
- コードで描き直した説明図や画像生成AIの「ゲームっぽい画面」は実機画面と称さない。
- 見開きでは最低一度、ゲーム画面に拡大注釈・撮影時コメント・実装版表示を添える。
- 本物のゲーム画面は原画として拡大する場合ニアレストネイバー補間でピクセルを保持。

### B：未実装の想像図「CONCEPT ART / NOT IN GAME」
この本を華やかにする**描き下ろし**：彼岸花と宇宙の表紙キービジュアル、3人のキャラデザイン候補、シルエット・衣装・機体三面図、3人の対話、宇宙遺跡、赤い生体天体、記憶の海、白い彼岸、8面のイメージアート、ボスの解剖図、共鳴必殺技、花弁のエネルギー、武器断面、幻想的な最終場面。
- 画像生成ツールを使用できるなら**絵として**各アートを生成し、元画像（できれば300dpi相当以上）、生成日時・プロンプト・版・採用状態を保存。利用可能な画像生成手段を最初に確認し、なければ自由に使える自作ドット絵／ベクターアート制作方法を採る。
- **画像生成ツールがないのに「生成した」と偽らない。** 明確な欠落と取得・制作計画を出す。
- 画像に文章を描かせて誤字を混入させない。日本語のタイトル、名前、説明は後工程で編集可能なテキストを合成。
- 同じ人物の原画はデザイン決定まで版を明示、決定後は原画・配色・特徴を参照してキャラの統一を優先。
- 「このコンセプト画はゲーム内画面を示すものではありません」を適切に表示。

### C：攻略と考証図「DIAGRAM / DEVELOPMENT」
相互作用チャート、世界線の枝、装置の推定内部構造、ボス部位、攻撃弾の軌道、3人の成長曲線、撮影前後の工程、色パレット。科学描画の美しさで魅せる。虚構の数値は実測か設計案か区別。

## 6. 本の物語体験（小説家と編集者への発注）
- 冒頭は**2ページの短編プロローグ**。たとえば「宇宙がひとつだった、最後の夜。」という書き出しから、3機が飛ぶ情景へ。大切な人「ヒカリ」が誰かは未決のため、人物関係を断定せず匿名性を保つ。
- 各キャラには性格が行動に出る200～450字の**短い情景描写**、大きな見せ場の一行、武器が生き方を映す説明を添える。
- 章ごとに、戦場の記録・研究室のメモ・回収された通信記録・星図の断片を散りばめる。情報量だけでなく余白に余韻を残す。
- 真相やヒカリの設定を勝手に解決せず、「暫定テキスト」「未確定の断章」と注記して文芸的魅力を作る。
- 「確定／未決」の編集タグを毎段落に大きく貼らない。巻末の設定台帳で管理し、本文では細い編集記号・脚注で必要十分に表示。

## 7. 科学考証（リアルな科学と作中仮説を分ける）
- 現実の脳科学では死者の記憶を宇宙へ転送して再会させる技術は確立していない。作中装置は**フィクションの仮説**と明記。
- 情報・記憶とエネルギーの扱い、位相同期、世界線の分岐、因果、記憶保存と欠損、共鳴のコストを**作中法則**として整える。
- ルール案：「失われた記憶を複製すると必ず別の記憶が欠損する」等はまだ提案であり採用前提にしない。
- キャラクター固有能力がゲーム的に説明できるようエネルギー源・制約・反動を考え、矛盾・例外一覧を作成。
- 生体兵器は構造・体内液・神経・可動機構を一貫させる。リアルの生命科学を超える箇所は作中技術の説明と分離。
- 出典と実在の科学知識は事実確認する。ゲーム内SF法則の「考証」は現実性を断定することではない。

## 8. 見開きレイアウト（最低6種）
1. **映画ポスター型**：絵80〜90%、文章は短いコピーだけ。
2. **キャラクター図鑑型**：大判立ち絵＋表情・機体図＋戦闘原理、見出しに個性。
3. **世界観美術型**：見開きパノラマ＋極小注記、空気の厚みで魅せる。
4. **小説断章型**：片頁の文学的本文＋片頁の大きな挿絵。
5. **実ゲーム解剖型**：本物の画面を大きく、番号付き注釈とスクリーンショット証跡。
6. **科学設定画型**：構造図＋断面図＋設計上の疑問、青写真のように。
7. **制作の軌跡型**：旧案→ラフ→改良→画面と時系列／採用理由。

## 9. 絶対に避ける表現
- 同じ大きさの本文と小さな装飾だけで26ページを量産する「Word資料」風。
- 文章を生成画像に埋め込んで日本語が崩れるページ。
- 公式原画が未承認なのに勝手に「完成版キャラ」とラベルする。
- 合成した画面を本物のゲームプレイ画面として掲載する。
- 僅かな画像を拡大してぼやけたまま商業印刷する。
- 著作権者が別にいる画像や『沙羅曼蛇』固有の素材を勝手に再利用する。
- 元の v0.1 を削除する／テスト済みでない機能をゲームで完成済みと記述する。

## 10. 実作業手順と納品（今すぐ着手）
1. 既存の `books/perfect-guide/v0.1/` と `docs/manjushage/`、AGENTS/HANDOFF、実ゲームコードを読み、既存の本が地味な理由を**ページ別**に編集診断。
2. `books/perfect-guide/v0.2/` を新規に作り、**改訂章立て＋見開きラフ全ページのサムネイル一覧**（ページID, 文字, 画像, 目的, 取得状況）を作る。
3. アートバイブル（色、フォント選定、組版グリッド、イメージ統一のルール）を作成。
4. 利用できるアート生成手段を確認し、可能ならまず**表紙 + キャラ3人 + 世界観2枚 + ステージ2枚 + 共鳴必殺技1枚**の計9点程度を元画像で制作。人物外見は**デザイン案**扱い。
5. 同時に現在のGodot試作を起動して本物のスクリーンショットを撮り、少なくともタイトル／プロローグ／道中／パズル／ボス／クリアなどの実画面を収集。
6. SF科学考証ノートと小説断章原稿を起こし、設定台帳に仮説と事実を分離。
7. **高密度な24〜32頁の試作PDF**を組版。原本ソース（画像、原稿、レイアウト）を同梱。
8. 全ページをPNGにレンダリングし、目次・文字化け・溢れ・画質・絵柄の不整合を視覚検査。コンタクトシートと目次、図版ID一覧を作る。
9. v0.1との違い、未制作の絵、未確定設定、実際に撮影できた画面、テスト結果を報告し、 `HANDOFF.md` と `docs/CHANGELOG.md` を更新する。
10. ユーザーの承認なく旧 v0.1 を破壊せず、Steam販売や「公式完成原画」「完成版攻略」を名乗らない。

### 受け入れ条件
- PDFのページを開いた瞬間、テキストよりも大判の美しいイラストが主役として感じられる。
- 3人それぞれの見開きが、名前・性格・戦闘スタイルだけで読み物として魅力的。
- 本物のゲーム画面と想像の絵を明確に見分けられる。
- 情報を削ったページにも文学的な余韻があり、世界の科学的・ゲーム的な一貫性がある。
- 文字と画像の原本を次版に引き継げる。正式名の誤りゼロ。
